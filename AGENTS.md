# Agent Guide for `architekton-py-example`

This file is for AI coding agents working in this repository. It states how
to run the checks and where edits belong. The human-facing contribution
guide is [.github/CONTRIBUTING.md](.github/CONTRIBUTING.md).

> Data-science project: `src/` holds the importable package (`src/architekton_py_example/`)
> beside the analysis pipeline stubs (`data/`, `features/`, `models/`,
> `visualization/`, each a `.gitkeep` stub). Promote notebook cells into
> tested modules there; the stubs are linted like any other `src/` code,
> so new third-party imports need a `[project] dependencies` entry first.
> Rename or extend the stubs via the `src_dirs` answer
> (`.copier-answers.yml`).


## Commands
The `task` task runner drives the common commands:

```sh
task fix            # auto-fix formatting and lint
task lint           # ruff format --check + ruff check (check-only)
task test           # pytest
task legal-check
task ethics-block
task check          # everything above
```

Run `task fix` before committing to apply formatting
and lint fixes, then `task check` (or `lint` + `test`
+ `type-check` individually) before finishing a change.

The repo-hygiene checks (secrets, workflow linting, YAML validity, the
conventional PR title) run in CI, not as local hooks — the lint and
fix tasks work anywhere, including outside a git repository.

Type checking uses basedpyright plus `pyrefly`; `deptry`,
`vulture`, and `typos` also run as part of type-check.


Build the docs with `task docs`.

## Where to edit

- Application/package code: `src/architekton_py_example/`
- Tests: `tests/`
- Docs: `README.md` and `docs/`

Keep 100% coverage where it exists; do not lower it.


Data, notebooks, and reports (`data/`, `notebooks/`, `models/`,
`reports/`) are analysis artifacts — keep generated outputs out of git.


## Production security defaults

These scaffold defaults are safe for local development and must change
before production. Details: `docs/explanations/security-defaults.md`
(if the render ships no docs tree, read the same page in the template
repository).

- Never commit real secrets: `.env`, `.envs/`, `*.pem` stay git-ignored
  (`.gitignore`), and `.env.example` carries only placeholder/commented
  values. The hygiene CI rejects committed secrets.












## Commits and CI

- Use [Conventional Commits](https://www.conventionalcommits.org/)
  (`feat:`, `fix:`, ...) in the PR title — hygiene CI checks the title
  only, and pull requests land via squash-merge. Individual commit messages
  are free-form.
- CI runs lint, type-check, and tests on every push
 plus a docs build; keep all of them green.

## Rules for this project

Rules from the [rulebook](https://github.com/politeuma/law-map/tree/main/guidance/sections) that match this project's `.daimonion.yml`
conditions. Follow the lines under each rule; its sources say where the rule comes from, and the

### AI and copyright — scraping, training and RAG code must keep the non-enjoyment purpose intact

- Do not bypass robots.txt or other access-refusal measures.
- Do not design RAG that retrieves and re-emits the protected expression itself; extract facts and concepts.
- Do not overfit or fine-tune on a specific body of works in order to imitate it.

Sources: [bunka.go.jp](https://www.bunka.go.jp/seisaku/chosakuken/aiandcopyright.html) · Details: [rulebook `baseline-copyright-ai`](https://github.com/politeuma/law-map/blob/8ba7170987ec356c9183f44e0d0b0eaa94d7c484/guidance/sections/baseline/copyright-ai.md)

### License drift — track each dependency's current license and keep BSL/SSPL out

- Check the current license when adding a dependency and match it against an allowlist.
- Do not let source-available licenses such as BSL/SSPL in without review.
- When a project forks (Terraform to OpenTofu, ...), move to the legitimate successor.

Sources: [hashicorp.com](https://www.hashicorp.com/blog/terraform-is-now-source-available), [opentofu.org](https://opentofu.org/faq/) · Details: [rulebook `baseline-license-drift`](https://github.com/politeuma/law-map/blob/8ba7170987ec356c9183f44e0d0b0eaa94d7c484/guidance/sections/baseline/license-drift.md)

### ML bias — build per-group evaluation, explainability and human review into evaluation

- Always report per-group performance, not just average accuracy.
- Dropping protected attributes does not remove discrimination; handle proxies.
- Require human review for decisions that affect life opportunities.

Sources: [nejm.org](https://www.nejm.org/doi/full/10.1056/NEJMc1919366), [eur-lex.europa.eu](https://eur-lex.europa.eu/eli/reg/2024/1689/oj) · Details: [rulebook `domain-ml-bias`](https://github.com/politeuma/law-map/blob/8ba7170987ec356c9183f44e0d0b0eaa94d7c484/guidance/sections/domain/ml-bias.md)
